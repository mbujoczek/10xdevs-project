# Product Requirements Document (PRD) - AI Flashcard Generator

## 1. Product Overview

AI Flashcard Generator is a web application designed to help students study more effectively by automating the flashcard creation process. The application uses artificial intelligence to generate flashcard suggestions based on user-provided text, significantly reducing the time required for preparation. Users can review, edit, and accept the generated flashcards and then use them in an integrated spaced repetition system (SRS) to optimize the memorization process. The MVP of the product focuses on core functionalities of generation, management, and learning, with a simple user authentication system.

## 2. User Problem

The main problem the product solves is the time-consuming and laborious nature of manually creating high-quality educational flashcards. Many students abandon the spaced repetition learning method because they are deterred by the need to create a large number of flashcards from study materials such as lecture notes or textbooks. This process is perceived as monotonous and discouraging, which limits the use of one of the most effective learning techniques.

## 3. Functional Requirements

### 3.1. User Authentication System

- A user can create an account by providing a unique username and password.
- A user can log in to their account using their username and password.
- The user session is managed using JSON Web Tokens (JWT).

### 3.2. Flashcard Generation from Text

- The user can paste or type text (up to 10,000 characters) into a dedicated text field.
- The application supports input text in Polish and English.
- The system uses a free AI model to analyze the text and generate a list of flashcard suggestions (candidates).

### 3.3. Flashcard Review Process

- After generation, the user is redirected to a dedicated review interface.
- For each flashcard suggestion, the user has three options:
  - Accept: Saves the flashcard without changes.
  - Edit: Allows modification of the question and/or answer before saving.
  - Reject: Removes the suggestion from the list.
- Changes (accepted, edited flashcards) are saved to the user's database only after clicking the "Finish Review" button.

### 3.4. Flashcard Management

- The user has access to a list view of all their saved flashcards (accepted and edited).
- The list displays the question and answer for each flashcard.
- The user can manually create new flashcards.
- The user can edit existing flashcards.
- The user can delete flashcards from their collection.

### 3.5. Learning Session (Spaced Repetition)

- The application integrates with a ready-made open-source library for handling the repetition algorithm (e.g., an SM-2 implementation).
- The user can start a learning session, during which the system presents flashcards for review.
- After viewing the answer, the user rates their knowledge of the flashcard on a 6-point scale (0-5).
- Based on the rating, the algorithm calculates and schedules the date of the next review.

### 3.6. Interface Multilingualism

- The user interface is available in Polish and English.
- The user can switch the interface language.
- The language choice is stored in the user's browser.

### 3.7. Flashcard Generation Statistics

- Collecting information on how many flashcards were accepted after being generated by the AI.

## 4. Project Boundaries

### 4.1. Features within MVP Scope

- User authentication based solely on login and password (JWT).
- AI-powered flashcard generation from pasted text (up to 10,000 characters).
- Manual creation, viewing, editing, and deletion of flashcards.
- Storing all user flashcards in a single, shared list.
- Integration with a ready-made, external SRS algorithm (e.g., SM-2).
- Learning session interface with a 6-point rating scale.
- Support for Polish and English for flashcard generation and the interface.

### 4.2. Features outside MVP Scope

- Advanced, proprietary repetition algorithm (like in SuperMemo or Anki).
- Importing files in formats like PDF, DOCX, etc.
- Creating "decks" or folders to group flashcards.
- Pagination, filtering, and searching on the flashcard list.
- Sharing flashcard sets between users.
- Integrations with external educational platforms.
- Dedicated mobile applications (iOS, Android).
- Logging in via third-party providers (e.g., Google, Facebook).
- "Forgot password" functionality and email verification.

### 4.3. Unresolved Issues and Risks

- The final choice of an open-source library for SRS requires further technical analysis.
- The quality of flashcards generated by a free AI model may be insufficient to achieve the assumed success metrics. Comparative tests should be conducted, and a contingency plan prepared.
- The user interface design for the mass flashcard review process requires detailed development in the UX/UI phase.

## 5. User Stories

### 5.1. Account Management

- ID: US-001
- Title: New user registration
- Description: As a new user, I want to be able to create an account in the application using a unique username and password, so that I can save my flashcards.
- Acceptance Criteria:

  - The registration form includes "Username" and "Password" fields.
  - The system checks if the username is already taken.
  - The password must meet minimum security requirements (e.g., 8 characters).
  - After successful registration, I am automatically logged in and redirected to the main dashboard.

- ID: US-002
- Title: Logging into the system
- Description: As a registered user, I want to be able to log into my account by providing my username and password to access my flashcards.
- Acceptance Criteria:

  - The login form includes "Username" and "Password" fields.
  - After correct authentication, I receive a JWT token.
  - After logging in, I am redirected to the main dashboard.
  - An appropriate message is displayed in case of incorrect credentials.

- ID: US-003
- Title: Logging out of the system
- Description: As a logged-in user, I want to be able to log out to securely end my session.
- Acceptance Criteria:
  - There is a "Logout" button in the interface.
  - After clicking the button, the session token is invalidated on the client side.
  - I am redirected to the login page.

### 5.2. Flashcard Generation and Review

- ID: US-004
- Title: Generating flashcards from text
- Description: As a student, I want to paste a fragment of my lecture notes so that the system automatically generates flashcard suggestions for me, saving my time.
- Acceptance Criteria:

  - The main page has a text field that accepts up to 10,000 characters.
  - After pasting the text and clicking the "Generate" button, the system starts the process in the background.
  - After generation is complete, I am redirected to the flashcard review view.

- ID: US-005
- Title: Reviewing generated flashcards
- Description: As a student, I want to quickly review the generated flashcards, accept the good ones, correct those that need improvement, and reject the weak ones to build a valuable study set.
- Acceptance Criteria:
  - The review view displays a list of flashcard "candidates," each with a question and answer.
  - Each suggestion has "Accept," "Edit," and "Reject" buttons.
  - Clicking "Accept" marks the flashcard as ready to be added.
  - Clicking "Reject" removes the suggestion from the list.
  - Clicking "Edit" opens a form allowing me to change the content of the question and answer.
  - After editing, I can save the changes, and the flashcard is marked as "edited."
  - After reviewing all suggestions, I click "Finish Review," which saves the accepted and edited flashcards to my account.

### 5.3. Flashcard Management

- ID: US-006
- Title: Manually creating a flashcard
- Description: As a user, I want to be able to manually add a new flashcard when I have a specific question and answer to remember.
- Acceptance Criteria:

  - There is an "Add new flashcard" button in the interface.
  - Clicking it opens a form with "Question" and "Answer" fields.
  - After filling it out and saving, the new flashcard appears on my flashcard list.

- ID: US-007
- Title: Viewing the flashcard list
- Description: As a user, I want to see all my flashcards in one list to have an overview of the material I am learning.
- Acceptance Criteria:

  - A "My Flashcards" page is available, which displays a list of all my flashcards.
  - Each list item shows the content of the question and answer.
  - The list does not have pagination or filtering options in the MVP.

- ID: US-008
- Title: Editing an existing flashcard
- Description: As a user, I want to be able to edit my existing flashcards to correct errors or update information.
- Acceptance Criteria:

  - There is an "Edit" option next to each flashcard on the list.
  - Clicking it opens a form with the pre-loaded content of the question and answer.
  - After saving the changes, the flashcard on the list is updated.

- ID: US-009
- Title: Deleting a flashcard
- Description: As a user, I want to be able to delete a flashcard that I no longer need.
- Acceptance Criteria:
  - There is a "Delete" option next to each flashcard on the list.
  - An operation confirmation is displayed after clicking.
  - After confirmation, the flashcard is permanently deleted from my account.

### 5.4. Learning

- ID: US-010
- Title: Starting a learning session
- Description: As a student, I want to start a learning session where the system will present flashcards to me according to the spaced repetition algorithm, so I can learn effectively.
- Acceptance Criteria:

  - There is a "Start Learning" button on the main page.
  - The system selects flashcards whose review date has passed.
  - If there are no flashcards to review, an appropriate message is displayed.

- ID: US-011
- Title: Rating an answer
- Description: As a student, after seeing the answer on a flashcard, I want to rate how well I knew it, so the algorithm can schedule the next review at the optimal time.
- Acceptance Criteria:
  - During the learning session, only the question is displayed at first.
  - The answer is revealed after clicking the "Show Answer" button.
  - Below the answer, there are 6 buttons with ratings (from 0 to 5).
  - After selecting a rating, the system saves it and moves to the next flashcard in the session.
  - A summary is displayed at the end of the session.

### 5.5. Settings

- ID: US-012
- Title: Changing the interface language
- Description: As a user, I want to be able to switch the interface language between Polish and English to use the application in my preferred language.
- Acceptance Criteria:
  - There is a language switcher in the interface (e.g., a flag or "PL/EN" abbreviation).
  - After changing the language, the entire application interface is immediately translated.
  - The language choice is saved in the browser's `localStorage` and is remembered on subsequent visits.

## 6. Success Metrics

### 6.1. AI Acceptance Rate

- Goal: At least 75% of AI-generated flashcards are accepted by users without editing.
- Measurement: Measured globally in the system as the ratio of the number of flashcards for which the user clicked "Accept" to the total number of generated flashcard candidates.
- Formula: `(Number of flashcards accepted without editing) / (Total number of generated candidates) >= 0.75`

### 6.2. AI Feature Adoption

- Goal: At least 75% of all newly created flashcards in the system come from the AI generator (and not from manual creation).
- Measurement: Measured as the ratio of the number of flashcards created using the AI generator (accepted and edited) to the total number of all newly created flashcards (from AI and manual).
- Formula: `(Number of flashcards from AI) / (Total number of new flashcards) >= 0.75`
